# For Eng Ahmed — How we measure "are we on schedule?"

*Prepared for CEO sign-off. Plain-language; no system jargon. Three decisions.*

## What this is about

The system already knows **how far along a project is right now** — it adds up the completed work
(from the daily site reports and verified quantities) into an overall "% complete." What it does
**not** yet know is two things every project manager wants:

1. **A planned line to compare against.** "We are 44% complete" only means something next to "we
   *should* be 52% complete by now." We need to know where a project was *planned* to be at each
   point in time, so the system can say **ahead / on track / behind**.
2. **A record over time.** Today the % is only "as of this moment." To draw the classic
   progress curve (planned vs actual over the months) and to compare this month against last month,
   the system needs to **freeze the numbers at regular points** and keep the history.

Once we have those two things, the **Performance** screen becomes a real early-warning tool (a
planned-vs-actual curve, and "6 days behind") instead of a single number, and the **Verified
Progress** screen can show "this month vs last month."

We need three decisions from you to build it right rather than guess.

---

## Decision 1 — Where does the *planned* line come from?

This is the important one. To say "you should be 52% by now," the system needs a plan to measure
against. How does ACCO decide what progress *should* be at a given date?

| Option | How it works | Best when |
|---|---|---|
| **A — From the programme/schedule** | Each work package (or milestone) carries a **planned start and finish date** and a weight; the system spreads its weight across its dates to build the planned curve. This is the standard construction "baseline programme." | ACCO plans work with dated packages/milestones. *(Needs us to start capturing a planned start/finish on each work package.)* |
| **B — Planned % entered by hand** | The project manager types the planned % for each month (e.g. "by end of March we plan to be at 20%"). | You already track a planned S-curve on paper/Excel and just want it in the system. |
| **C — Simple line from start to end date** | The system draws a straight (or standard S-shaped) line from the contract start date to the expected finish date. No extra data entry. | A quick, honest placeholder until a real programme exists. |

**Our recommendation:** **A**, if ACCO maintains dated work packages/milestones — it's the real,
professional answer. If not yet, we start with **C** (honest, zero effort) and upgrade to **A** when
the programme is captured. We'd only pick **B** if you already keep a planned %/month today.

→ *Please pick A, B, or C — and if A, confirm we should add a **planned start/finish date** to each
work package.*

## Decision 2 — Is the plan *frozen*, or can it change?

Best practice on a real project: you set a **baseline** at the start and measure everything against
it, so "behind schedule" always means "behind the plan we committed to." If the plan genuinely
changes (a variation, a re-sequence), you record a **new baseline** on purpose — and the system
keeps the old one so the change is visible and auditable.

→ *Please confirm: the planned line is a **frozen baseline**, and re-planning is an explicit, recorded
action (not silently editable).* — **Recommended: Yes.**

## Decision 3 — When do we "freeze" the actual numbers?

To build the history (the curve, and month-vs-month), the system takes a snapshot of the real % at
regular points. When?

| Option | When the snapshot is taken |
|---|---|
| **At month-end close** *(recommended)* | When you close the accounting month. This matches how progress is billed and reported, and it's auditable — the frozen % is "what we reported for that month." |
| At each payment claim (IPC) | When a progress certificate is issued. |
| Weekly / on demand | A snapshot every week, or a button someone presses. |

**Our recommendation:** **month-end close** — it lines up with billing and reporting, and gives one
clean, trustworthy figure per month. (We can add "on demand" later if you want a mid-month look.)

→ *Please confirm month-end, or tell us the rhythm you want.*
